## Что умеют приложения

| | №1 — консоль | №2 — графический интерфейс |
|---|---|---|
| Ввод | Фамилия и имя с клавиатуры | Группа и студент из выпадающих списков |
| Билет | Случайный номер от 1 до 20 | Номер и три вопроса из Word |
| Повторный студент | Новая случайная выдача | Первый назначенный билет |
| Сохранение | После каждого студента | Перед показом результата |
| Выход по ESC | Завершает программу | Закрывает только окно результата |

Приложения дописывают журнал, обрабатывают недоступные файлы и сохраняют предыдущие записи. №2 — настоящее приложение Tkinter. В Docker его окно передаётся через noVNC в браузер.

## Стек

- **Python 3.12**, **prompt_toolkit** — консольный ввод и ESC.
- **Tkinter / ttk** — настольный интерфейс.
- **openpyxl** — чтение и запись Excel; **python-docx / lxml** — чтение Word.
- **pytest**, **unittest.mock** — проверки логики; Tkinter — автоматическая проверка GUI.
- **Docker Compose**, Xvfb, Openbox, x11vnc и noVNC — контейнерное окружение №2.
- **Git / GitHub** — история разработки. Отдельной базы данных нет.

## Быстрый запуск в Docker

Нужны Git и Docker Desktop с работающим движком **Linux containers / WSL 2**. Команды выполняются в PowerShell из корня репозитория.

### №1 — консоль

```powershell
git clone https://github.com/aristique/ai-ticket-generator.git
cd ai-ticket-generator
docker compose build lab1
docker compose run --rm lab1
```

Введите фамилию → Enter, имя → Enter. Программа выдаст номер и сохранит запись. **ESC** завершает ввод без ожидания Enter. Для этой работы нужен интерактивный терминал.

### №2 — окно с билетами

```powershell
docker compose build lab2
docker compose run --rm lab2 python -m ui_tickets.samples /data
docker compose up -d lab2
```

Откройте [рабочий стол приложения](http://localhost:6082/vnc.html?autoconnect=true&resize=scale).

Команда `samples` создаёт **вымышленные демонстрационные** Excel/Word-файлы и не перезаписывает существующие. Выберите группу и студента, нажмите кнопку генерации. ESC возвращает к выбору.

Остановка: `docker compose stop lab2`. Удаление контейнеров: `docker compose down`. Данные в папке `data` остаются.

## Как подготовить студентов и билеты

Все входные файлы №2 находятся в **`data/lab2/`**.

### Студенты — students.xlsx

Один лист Excel = одна группа. Имя листа, например `TI-237`, отображается в интерфейсе. В первой строке заголовки; данные начинаются со второй:

| A — Фамилия | B — Имя |
|---|---|
| Иванов | Иван |
| Петрова | Анна |

Новая группа добавляется созданием листа; новый студент — строкой на нужном листе. Пустая группа разрешена: выдача билета в ней недоступна.

### Билеты — tickets.docx

Каждая строка примера — отдельный абзац Word:

```text
Билет 1
1. Что такое программная инженерия?
2. Какие существуют уровни тестирования?
3. Для чего нужен Git?

Билет 2
1. Что такое unit-тест?
2. Для чего используется Docker?
3. Что такое Pull Request?
```

Поддерживается буквальная и штатная нумерация Word. У билета должно быть минимум три вопроса. Некорректные билеты пропускаются, причины записываются в `application.log`. Программа выбирает из готовых билетов; ИИ во время выдачи не вызывается.

После изменения файлов сохраните их и нажмите **«Перечитать входные файлы»**. Во время выдачи не меняйте номера назначенных билетов: повторный выбор ищет именно первый номер.

## Где сохраняются результаты

| Файл | Содержимое |
|---|---|
| `data/lab1/journal.xlsx` | Фамилия, имя, номер билета, дата и время №1 |
| `data/lab2/students.xlsx` | Группы и студенты №2 |
| `data/lab2/tickets.docx` | Билеты и вопросы №2 |
| `data/lab2/results.xlsx` | Группа, фамилия, имя, номер, дата и время, повтор |
| `data/lab2/application.log` | Диагностика чтения входных данных |

Журналы создаются автоматически при сохранении первой записи. Идентификатор студента №2 — **группа + фамилия + имя**. Повторная выдача добавляет строку «Повтор = да» с прежним билетом.

Закрывайте журнал в Excel перед выдачей. При блокировке приложение предлагает повторить сохранение. Используйте один экземпляр приложения на журнал.

## Тестирование

```powershell
docker compose run --build --rm test-lab1
docker compose run --build --rm test-lab2
```

| Файл | Проверки |
|---|---|
| [test_cli.py](lab1-console/tests/test_cli.py) | Ввод, пустые значения, цикл и ошибки |
| [test_journal.py](lab1-console/tests/test_journal.py) | Дописывание Excel, блокировки, сохранность данных |
| [test_process.py](lab1-console/tests/test_process.py) | Настоящий процесс, перезапуск и ESC в Linux pty |
| [test_sources.py](lab2-desktop/tests/test_sources.py) | Студенты, Word, некорректные билеты |
| [test_service.py](lab2-desktop/tests/test_service.py) | Первый билет, повторы, история и ошибки |
| [test_gui.py](lab2-desktop/tests/test_gui.py) | Выбор, доступность кнопки, результат, ESC и сохранение |

В исходной Linux-проверке прошли 16 тестов №1 и 17 тестов №2. Локальная Windows-проверка также выполнена, при этом два Linux-теста процесса исключены. Проверка блокировки **настоящим Excel** остаётся отдельным ручным сценарием. Selenium здесь не используется: UI нативный.

## Структура проекта

```text
lab1-console/

    journal.py      # Excel-журнал

  tests/

    sources.py      # Чтение Excel и Word
    service.py      # Назначение билетов и журнал
    samples.py      # Демонстрационные данные
    __main__.py     # Точка входа

data/               # Рабочие файлы, исключены из Git
docs/               # План и инструкции
compose.yaml        # Приложения и тестовые контейнеры
```
