# Lab 2 request for GitHub Copilot Chat

Implement a standalone Python/Tkinter desktop exam-ticket generator under lab2-desktop.
Preserve independent execution of lab1-console. Use a separate Docker image and Compose service.
Use a virtual desktop with noVNC, accessible through a localhost-only port from a browser on Linux or Windows Docker Desktop.
The product is a desktop GUI streamed to the browser, not a replacement web form.
Keep all runtime dependencies in Docker. Persist input/output files in data/lab2.

Inputs:
- students.xlsx: sheet name is group name; row 1 is header, column A last name, B first name; students start at row 2.
- tickets.docx: headings "Билет N"; three numbered question paragraphs per ticket.
- Support both literal "1. text" paragraphs and Word's native numbered-list paragraphs.
- Include fictional demonstration inputs and a separate explicit setup command to copy them into the data directory; do not silently recreate missing production sources at startup.

UI:
- On launch load group names from Excel.
- The generate button is disabled until both group and student are selected.
- Changing group clears previous student selection, even if names happen to match.
- Empty groups leave an empty student list and disabled button.
- Generate opens a result window with "Ваш билет № N" and the three questions.
- ESC closes the result window and returns to selection; it must not close the main application.

Journal:
- results.xlsx columns: Группа, Фамилия, Имя, Номер билета, Дата и время, Повтор.
- Student identity is group + last name + first name.
- For a new student select a random valid ticket.
- For an existing student use the ticket from the FIRST matching chronological journal row.
- Append a NEW row on EVERY successful generation. Repeat flag is "нет" for first occurrence and "да" thereafter.
- Never replace earlier rows or silently choose another ticket for an existing student.
- Save immediately, not on exit.
- If saving is blocked, keep the pending assignment and retry without redrawing or duplicating the entry.
- Display successful completion only after the assignment has been persisted.

Errors and parser:
- Missing input files: clear message, no crash.
- Skip malformed tickets (unrecognized heading / fewer than 3 questions), log an actionable error and continue with valid tickets.
- After skipping malformed tickets, draw only from IDs actually present in the valid-ticket map. Do not renumber tickets or accidentally select a skipped ID.
- No valid tickets: clear message and disabled generation.
- Reject ambiguous duplicate ticket IDs with a logged message.
- If a journal's original ticket is no longer present in Word, report it instead of assigning a replacement.
- Preserve corrupt/incompatible existing journals; do not overwrite them.
- Treat spreadsheet names as text rather than formulas.

Structure and acceptance:
Separate source parsing, assignment/journal logic and Tkinter UI so core functions are unit-testable without the desktop.
Add tests for Word parsing, group filtering, first-record ticket reuse, append-only repeat history, empty groups, malformed tickets and save retry.
Use real XLSX/DOCX fixtures generated by test helpers where needed.
Add a GUI smoke test inside a virtual display.
Document one command for tests and one for running the desktop.
Keep separate pinned application/test dependencies and meaningful incremental Git commits.
Before calling the lab complete, verify group selection, button state, displayed questions, repeated assignments, ESC, journal persistence and missing/blocked files.
Record the actual Copilot model, actions, errors and manual corrections without inventing provenance.
